# 文档写作规范

适用于 FlexKVM 所有中文技术文档。

## 受众与站位（最高优先级）

本仓库的文档是**给用户看的**，读者是设备用户，不是开发者。以下条目都属于"禁止项"，与语言风格冲突时以本条为准。

- **只写用户能感知的东西** — 用户要完成什么、点哪里、看到什么、出错怎么办。用户看不到、用不上、不关心的内容不写
- **不写工程实现** — 模块划分、线程与进程、总线与事件名、协议字段与命令、errno 与返回码、设备节点与挂载参数、依赖库、内部函数名、构建与仓库工程细节，一律不进正文
- **解释"为什么"也只到用户层** — 写"小于 512 字节的文件被控端无法识别"，不写"内核某函数要求介质至少一个扇区"；写"状态每隔几秒自动更新"，不写"后端每 3 秒轮询控制面"
- **同功能的多次提交合并成一条** — 开发期把一个功能拆成多个提交是常态，文档按**用户可见的结果**写一条（"新增 xxx"），不逐条罗列实现步骤、修复过程或重构
- **自检**：这句话会让用户做出不同的操作选择吗？不会就删掉

## 禁止项

- **禁止使用"上图"、"下图"、"如上图所示"** — 改用描述性语句说明图片内容，或直接用标题+图片的结构
- **禁止使用"可以看到"** — 直接陈述事实
- **禁止使用"这个是一个"、"这个是"** — 删除冗余主语
- **禁止使用"会"做填充词** — "点击后会弹出" → "点击后弹出"
- **禁止口语化评价** — "稍微有点麻烦"、"挺方便的"等主观感受不应出现

## 表述原则

- **直接陈述，不铺垫** — "可以看到界面中有两个区块" → 直接说"界面包含两个区块"
- **操作步骤用祈使句** — "用户可以根据自己的需求选择" → "根据需求选择"
- **描述 UI 用名词，不用方位** — "上图的红色框框的位置" → "菜单栏中的屏幕按键"
- **功能说明用"功能 → 效果"结构** — 先说是什么，再说能干什么

## 用词一致性

术语、档位名、默认值以 [`.agents/TERMS.md`](../../TERMS.md) 为准。跨页口径最易出错的几处：

- 按键 A / 按键 B 的分段行为（配网、直连、热点、返回主界面）
- 配网热点 `flexkvm-conf`（密码见 OLED）与 AP 热点 `FlexKVM-AP` / `12345678`
- 画质档名统一为「低 / 中 / 高 / 极高」，不写"超高""最佳"
- 状态词统一为「未使能」，不写"已禁用""已关闭"

## 示例

| 问题写法 | 修正写法 |
|---------|---------|
| 上图的红色框框的位置为屏幕按键，左边的图标为一个显示器的图标 | 菜单栏中的屏幕按键，图标为显示器样式 |
| 可以看到，屏幕菜单中包含了以下选项 | 屏幕菜单包含以下选项 |
| 这个是一个选择器用来切换 flexkvm 的 edid | EDID 选择器用于切换 EDID 配置 |
| 相对模式的话，控制会稍微有点麻烦 | 相对模式需要点击远程画面后才能控制 |
| 点击之后，会弹出一个模态框 | 点击后弹出模态框 |
| 如上图所示，左边的图标表示为显示连接成功 | （删除整句，图片下方自然承接） |
| 状态不是实时推送的：后端每 3 秒查询一次本地控制面 | 状态每隔几秒自动更新一次，不是实时的 |
| 小于 512 字节的文件会被拒绝（内核要求介质至少一个扇区） | 小于 512 字节的文件会被拒绝（被控端无法识别这么小的介质） |
| 前端不校验 `etk_` 前缀，两种都合法 | 两种都合法，不需要管开头是什么 |
| 版本直接读二进制，守护进程没在跑时也能显示 | 服务没在运行时版本号照样显示 |
| 修复 NFS/SMB 挂载卡在 Mounting 的双重兜底与队列丢弃问题 | 修复 NFS/SMB 挂载一直卡在「挂载中」的问题 |
