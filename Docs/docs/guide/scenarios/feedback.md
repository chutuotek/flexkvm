## 第二步：收集诊断信息

自查没解决？提交反馈前，把这几个信息准备好——开发者能少问好几轮。

### 必须有的

| 信息 | 在哪看 |
|------|--------|
| FlexKVM 固件版本 | Web 界面 → 设置 → 关于，或 OLED 底部 |
| 你的操作系统版本 | Windows / macOS / Linux 的系统信息 |
| 浏览器版本 | Chrome：地址栏 `chrome://version`；Edge/Firefox：设置 → 关于 |
| 问题发生时间 | 记个大概就行 |
| 复现频率 | 单次 / 偶尔 / 每次必现 |
| 问题描述 | 什么场景触发的、具体现象是什么 |

### 系统日志

进 Web 界面 → 设置 → 维护，导出两个日志：

- **后端日志**（日志管理 → 下载）
- **Web 日志**（WEB 日志卡片 → 自动下载）

> ⚠️ **问题发生后立刻导出**，别重启设备后再导——重启会清掉关键信息。
>
> 日志保留规则、下载校验、文件命名说明 → [系统日志](../maintenance/log.md)

### 截图或录屏

一张出问题时的截图比几百字文字描述都直观。如果问题涉及操作步骤，录一段屏幕更好。

## 第三步：提交反馈

### Bug 反馈渠道

| 渠道 | 适合 | 地址 |
|------|------|------|
| GitHub Issue | 公开跟踪 | [github.com/chutuotek/flexkvm/issues](https://github.com/chutuotek/flexkvm/issues) |
| Gitee Issue | 国内访问快 | [gitee.com/chutuotek/flexkvm/issues](https://gitee.com/chutuotek/flexkvm/issues) |
| 邮箱 | 涉及隐私/企业信息 | [feedback@chutuotek.com](mailto:feedback@chutuotek.com) |

提交 Issue 时选对标签：**bug**（Bug）/ **documentation**（文档）/ **enhancement**（功能建议）。

### 好的反馈 vs 不好的反馈

**❌ 不好的反馈：**

> 远程桌面画面卡住了，重启也不行，快修一下。

开发者看到：不知道版本、不知道怎么触发、不知道日志在哪——只能追问，一来一回好几天。

**✅ 好的反馈（直接抄这个格式）：**

```
FlexKVM 版本：v0.1.2（设置 → 关于 → 系统版本）
操作系统版本：Windows 11 23H2
浏览器版本：Chrome 148.0.7778.178
出现时间：2026-05-25 14:30
出现频率：每次远程装机时必现

复现步骤：
1. 挂载 Win11 ISO，通过 ATX 重启被控设备
2. 进入 BIOS 后选择从 USB 启动
3. 安装界面出现后约 10 秒，远程画面冻结
4. 刷新浏览器后恢复，但 10 秒后再次冻结

已尝试的排查：
- 重启 FlexKVM → 无效
- 换 Chrome / Edge / Firefox → 均复现
- 换 HDMI 线 → 无效
- 降低画质到最低档 → 无效

附件：系统日志、冻结时截图
```

**为什么这个好？**

| 要素 | 作用 |
|------|------|
| 版本、系统、浏览器 | 判断是否和特定版本有关、是否已修复 |
| 精确复现步骤 1→2→3→4 | 开发者照着走一遍就能定位 |
| "每次必现" | 不会被当偶发问题搁置 |
| 已尝试的排查 | 避免开发者回复"试试重启/换浏览器"的无效往返 |
| 带了日志 | 日志里的时间线和错误堆栈比任何描述都准 |

> **写复现步骤的技巧**：想象你在教一个没用过 FlexKVM 的人操作。"挂载 ISO 然后重启"不够——"进镜像菜单 → 选分区 → 挂载 → 勾选 ISO → 共享文件 → 退出 → 点 ATX 电源 → 短按复位键 → 等 OLED 显示 BIOS 画面"才行。

### 功能建议

有好想法不需要完整方案，一句话也行：

- 希望支持的功能（NFS 远程挂载、更多分辨率、SNMP 监控…）
- 现有功能的改进（虚拟键盘可拖拽、快捷键优化…）
- 你在其他产品上用过的好体验
