# ZeroTier

ZeroTier 是 FlexKVM 上的虚拟组网工具——把设备加入同一个虚拟二层网络，之后不管它挂在什么网络后面，都能用网络里分配的成员地址（如 `10.52.234.173`）直接访问，不需要公网 IP、不用配路由器端口转发。与 Tailscale 不同，ZeroTier 没有登录这一步：设备身份由本地的 identity 文件自持，加入网络即成为成员。

> 入口：设置 → 应用 → ZeroTier

> 先在 [ZeroTier Central](https://central.zerotier.com) 创建（或加入）一个网络，拿到 16 位 **Network ID**（如 `b9a18a606f3352e0`）。把设备加进网络需要该网络的管理员权限；**私有网络**还要在网络控制台把本节点授权，否则网络状态会停在「未授权」。

![ZeroTier 设置](./images/zerotier/setting_zerotier.webp)

## 安装

ZeroTier 在 FlexKVM 上以应用形式提供。设备上还没装时，卡片显示**应用未安装**，服务开关和网络输入框都不会出现：

![ZeroTier 应用未安装](./images/zerotier/setting_zerotier_not_installed.webp)

在卡片的**应用管理**行里装一次：

1. 点**应用管理**打开更新面板
2. 点**检查更新**（必须先成功检查一次，后面的下载入口才会出现）
3. 未安装时按钮显示**下载**；下载完成会自动校验安装包，按钮变为**立即安装**，点它安装
4. 安装**不可取消**，完成后不需要重启设备

> 下载源切换、检查与下载的完整流程、失败原因见[应用管理](../maintenance/upgrade-app.md)。

> **验证**：卡片上的**应用未安装**提示消失，服务开关与网络 ID 输入框出现。

## 启用服务

点开关即可启用，立即生效——后端会拉起设备上的 zerotier-one 守护进程。应用未安装时不会出现这个开关，请先按上一节安装。

启用后开关下方显示**版本号**（如 `v1.16.2`）；发现新版本时追加 `(可更新)`，可以到**应用管理**里更新。

> **验证**：开关变为打开状态，卡片标题右侧出现**刷新**图标（未启用时没有这个图标）。

## 加入网络

在**网络 ID**输入框里填 16 位十六进制网络号（Network ID），点**加入**（在输入框里直接回车也可以）：

1. 从 ZeroTier Central 的网络页面复制 Network ID（16 位十六进制，如 `b9a18a606f3352e0`）
2. 粘贴到输入框，点**加入**
3. 加入是**同步受理**：本地控制面接受后立即返回，成员配置随后下发

网络会先显示**正在获取配置**，拿到地址后变为**已就绪**：

> **验证**：提示「加入 指令已发送」；卡片的输入框收掉，变成**详细信息**入口，副标题显示 `在线 · 1/1 个网络就绪`。

![ZeroTier 已加入网络](./images/zerotier/setting_zerotier_joined.webp)

> 输入不是 16 位十六进制时会直接提示「网络 ID 必须是 16 位十六进制」，不会发到设备。

> **私有网络**（`PRIVATE`）加入后，需要网络管理员在 ZeroTier Central 授权本节点；未授权时网络状态停在**未授权**，也拿不到成员地址。

> **只允许接入一个网络**：未接入时界面给输入框，接入之后输入框收掉、只剩**详细信息**入口；后端也会拦下第二次加入。要换网络，先在**详细信息**里**离开**当前网络。

## 网络选项

ZeroTier 网络有几项成员级选项：是否接受控制面下发的地址与路由、是否允许默认路由、是否允许全局地址等。**设置页不提供这些开关**——FlexKVM 在加入网络时就把它们定好了：

| 选项 | 加入时的取值 | 说明 |
|------|--------------|------|
| 接受控制面下发的地址与路由 | 保持默认（开启） | 成员地址与该网段的接口路由正是靠它下发，关掉这个网络就没有 IP |
| 默认路由 | 固定关闭 | 默认路由进隧道等于自断管理通道 |
| 全局地址 | 固定关闭 | 不把全局地址装进隧道 |

其他选项（例如控制面下发的 DNS）加入时不改写，保持 ZeroTier 的默认行为。这组取值写在设备上该网络的本地配置里，**重启守护进程后仍然生效**。

> 归结起来是两句话：**不接管路由**——默认路由和全局地址都不会进隧道；**照常拿地址**——成员地址与该网段的接口路由正常工作。
>
> 需要临时改这些选项（排障或二次开发）时，控制端点仍然可用，只是不在设置页出现。

## 网络详情

卡片上的**详细信息**入口汇总本节点的连接事实与已接入的网络，只在服务已启用且已接入网络时出现（副标题是 `在线/离线 · x/y 个网络就绪`）：

![ZeroTier 详细信息](./images/zerotier/setting_zerotier_detail.webp)

| 字段 | 说明 |
|------|------|
| 节点地址 | 本节点的 10 位十六进制 ZeroTier 地址；服务未启用时为空 |
| 连接状态 | **在线** = 至少与一个根节点或对端连通；**离线** = 一个都连不上 |
| TCP 中继 | **已启用** = UDP 完全打不通，正走 ZeroTier 的 TCP 中继兜底（能用但延迟更高）；正常显示**未启用** |
| 网络 ID | 该网络的 16 位网络号 |
| 网络状态 | 成员状态，见下表 |
| 地址 | 控制面分配的成员地址（含掩码，如 `10.52.234.173/24`）；还没下发时显示**尚未分配地址** |
| 接口 | 该网络在本机上的 TAP 接口名（如 `zt3hhlsmup`） |
| 网络 | 网络名（由控制面下发；没有名字时这一行不显示） |

网络状态：

| 状态 | 含义 |
|------|------|
| 已就绪 | 成员配置已下发，可以按地址访问 |
| 正在获取配置 | 刚加入，等控制面下发地址与路由 |
| 未授权 | 私有网络还没在网络控制台授权本节点 |
| 网络不存在 | Network ID 不存在（多半是填错了） |
| 接口创建失败 | 在本机创建 TAP 接口失败 |
| 客户端版本过低 | 控制面要求更高的 zerotier-one 版本 |
| 需要认证 | 控制面要求认证 |
| 未知状态 | 控制面返回了界面不认识的词，原样显示 |

> 状态不是实时推送的：后端每 3 秒向本地控制面查询一次（加入/离开后的 30 秒内提速到 500ms），所以地址下发、网络变**已就绪**最多有几秒延迟。点卡片标题右侧的**刷新**图标可以立即查询一次。

## 对端列表

ZeroTier 是点对点网络：设备和哪些节点连通、走哪条路径（UDP 直连还是中继），都记在**对端（peer）**里，包含地址、角色、版本、延迟与路径列表。

> **设置页不提供对端列表入口。** 对端数据由 WS 端点（`event_type` 为 `zerotier`、`type` 为 `peers`，需登录）返回，内容是本地控制面原样返回的数组，字段随 zerotier-one 版本变化。日常远程访问只需要**详细信息**里的**地址**，不需要看对端。

## 远程访问

加入网络并拿到成员地址后，**在你要访问 FlexKVM 的设备上也装 ZeroTier 并加入同一个网络**（私有网络同样要授权），然后：

- **Web 界面**：`https://<成员地址>`（如 `https://10.52.234.173`）
- **SSH**：`ssh <用户名>@<成员地址>`

数据走的是该网络在本机上的 TAP 接口，与设置页的网页界面无关——两端在同一个网络里，访问就像在同一根网线后面，能穿透 NAT 和防火墙。

## 离开网络

打开**详细信息**，在该网络下方点**离开**：

设备会拆掉这个网络的 TAP 接口与地址，该网络从成员表里移除。

> **验证**：提示「离开 指令已发送」；卡片回到未接入形态——重新出现**尚未加入任何网络**与网络 ID 输入框，**详细信息**入口消失。要换网络的话，这时填新的 Network ID 即可。

## 应用管理

卡片上的**应用管理**行是 ZeroTier 应用包的在线更新入口（与 Tailscale、frp 各自独立），点开后有：

| 操作 | 说明 |
|------|------|
| 下载源 | **GitHub** / **Gitee**；切源会清掉已下载的安装包与在线信息，需要重新检查更新 |
| 检查更新 | 从当前下载源拉取最新版本信息，行内显示上次检查时间 |
| 下载 | 下载安装包并校验完整性（显示进度、速度、剩余时间，可随时取消） |
| 立即安装 | 校验通过后出现；安装不可取消，失败自动回滚到旧版本 |
| 卸载应用 | 仅在已安装时出现；停止服务并删除应用文件（含安装时的备份） |

> 卸载会把服务开关置回关闭；重新安装后需要手动再打开开关。
>
> 每个应用只有一个任务槽：检查更新、下载、安装、卸载任一时刻只能有一个在跑，此时再点会提示「有其它更新任务正在进行,请稍后再试」。

完整流程（各状态含义、失败原因）见[应用管理](../maintenance/upgrade-app.md)。

## 故障排查

| 现象 | 可能原因 | 先试这个 |
|------|----------|---------|
| 卡片显示**应用未安装**，开关不出现 | 设备上没有 ZeroTier 应用包（未安装或验签失败） | 在卡片的**应用管理**里检查更新后安装 |
| 提示「网络 ID 必须是 16 位十六进制」 | 网络号填错：长度不对或含非十六进制字符 | 回到 ZeroTier Central 复制完整的 16 位 Network ID |
| 加入后网络状态一直**正在获取配置** | 成员配置还没下发（正常最多几秒） | 稍等几秒；点卡片右上角**刷新**图标立即查询一次 |
| 网络状态**未授权** | 私有网络没有在网络控制台授权本节点 | 在 ZeroTier Central 的成员列表里授权该节点 |
| 网络状态**网络不存在** | Network ID 不存在 | 核对 Network ID 是否抄错 |
| 加入失败，提示已接入其它网络 | 产品只允许接入一个网络 | 先在**详细信息**里**离开**当前网络，再加入新的 |
| 加入失败，提示服务未启用 | 守护进程没在跑（开关没打开） | 打开服务开关后重试 |
| 开关已打开，描述显示**服务未运行** | zerotier-one 进程异常退出 | 关掉开关再打开重新拉起；仍不运行就重新安装应用 |
| **TCP 中继**显示**已启用** | UDP 直连完全打不通，走了 TCP 兜底 | 检查设备所在网络是否限制 UDP 出站；中继能用但延迟更高 |
| 状态变化很慢 | 状态来自 3 秒一轮的轮询，不是实时推送 | 点卡片右上角**刷新**图标立即查询 |
| 服务已启用但看不到**详细信息** | 还没接入任何网络 | 填 Network ID 后点**加入** |
| 远程连不上 | 控制端没装 ZeroTier、没加入同一网络，或私有网络未授权 | 在控制端加入同一网络，确认能访问成员地址 |
